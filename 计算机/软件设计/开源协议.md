> 开源协议是作者给出的授权声明：别人能拿你的代码做什么、必须履行什么义务；核心分野只有一条——**宽松型**（照做署名就行）还是**copyleft 型**（衍生作品必须同样开源）。

## 没有协议不等于随便用

这是最重要也最反直觉的一条：**代码放在 GitHub 上公开，不代表别人可以随便用。**

在著作权法体系下，作品默认是「保留全部权利」的。你不加协议，法律上的默认状态是**除了浏览，别人什么都不能做**——不能用、不能改、不能分发。

所以给公开仓库加 `LICENSE` 文件不是走形式，而是**你想让别人用的话就必须做的事**。反过来，你要用别人的代码时，先看他有没有协议；没有的话，严格来说不能用，得去问作者。

## 两大阵营

抛开条款细节，所有协议先按一条线分类：**别人拿你的代码改完之后，他的成果是否也必须开源。**

**宽松型（permissive）** —— 不必。别人可以拿去闭源、拿去卖，只要保留你的版权声明。代表：MIT、Apache 2.0、BSD。

**Copyleft 型** —— 必须。衍生作品得用同样的协议发布，源码得公开。代表：GPL、AGPL。中文有时译作「著佐权」，也常被叫作「传染性」。

**只有 GPL 系是 copyleft，MIT 和 Apache 2.0 都是宽松型，允许闭源衍生。**

## 三个最该搞清楚的

| | MIT | Apache 2.0 | GPLv3 |
| --- | --- | --- | --- |
| 商用 / 修改 / 分发 / 私用 | 允许 | 允许 | 允许 |
| 明确授予专利权 | 否 | **是** | 是 |
| 必须保留版权与协议声明 | 是 | 是 | 是 |
| 必须说明改动了什么 | 否 | **是** | 是 |
| 必须公开完整源码 | 否 | 否 | **是** |
| 衍生作品必须用同一协议 | 否 | 否 | **是** |
| 商标使用限制 | — | **有** | — |

**MIT** —— 最短最宽松，条件只有一条：保留版权和许可声明。个人项目、库、工具，选它基本不会错。它**不包含明确的专利授权**。

**Apache 2.0** —— 在 MIT 的基础上多了两件事：**明确授予专利权**，以及要求**标明你改了什么**。同时对商标使用有限制。企业项目和大型基金会项目偏爱它，因为专利条款降低了下游被专利诉讼的风险。

**GPLv3** —— 强 copyleft。任何使用它的衍生作品**必须以相同协议发布，并提供完整源码**。它也授予专利权。适合「我希望这份代码及其所有衍生品永远保持开源」的立场。

## 另外几个会遇到的

**AGPLv3** —— GPL 的加强版，堵上了「SaaS 漏洞」。GPL 只在**分发软件**时触发义务，如果你把改过的 GPL 软件放在服务器上提供网络服务、并不分发二进制，义务就不触发。AGPL 把「通过网络提供服务」也算作触发条件。很多数据库和基础设施软件选它，正是为了防止云厂商直接拿去做托管服务而不回馈。

**LGPLv3** —— 弱化的 GPL，主要用于库。你的程序**链接**一个 LGPL 库，不会因此被要求开源；但你改了这个库本身，改动部分要开源。

**MPL 2.0** —— 文件级 copyleft。改了的**那些文件**要开源，你自己新加的文件不受影响。介于宽松和 GPL 之间。

**Unlicense / CC0** —— 接近放弃所有权利，进入公共领域。

## 怎么选

**做库或工具，希望被广泛使用** → MIT。门槛最低，企业采用无顾虑。

**项目有专利风险，或面向企业** → Apache 2.0。专利授权条款对双方都是保护。

**希望衍生作品必须保持开源** → GPLv3。

**上面这条，且要防止云厂商白嫖** → AGPLv3。

**跟着生态走。** 有些语言社区有默认习惯（Rust 生态常见 MIT OR Apache-2.0 双协议）。跟随惯例能减少使用者的顾虑。

**拿不准就 MIT。** 它最容易被理解和接受。协议可以在后续版本里更换（前提是所有版权持有者同意），但已经发布的版本不能追溯收回。

## 用别人代码时的注意事项

**GPL 有传染性，商业项目要当心。** 在闭源产品里引入一个 GPL 库，可能导致整个产品被要求开源。企业通常明令禁止引入 GPL 代码。用之前先确认依赖树里有没有。

**协议兼容性是个真问题。** 不是任意两个协议的代码都能合在一起。宽松协议的代码可以并入 GPL 项目（结果整体按 GPL 走），反过来不行。

**依赖的依赖也算。** 你直接依赖的库是 MIT，但它依赖了一个 GPL 库，风险照样传导过来。有专门的工具做许可证扫描。

**协议不等于免责。** 几乎所有开源协议都包含「不提供任何担保、作者不承担责任」的条款，这是它们共有的限制项。

## 在 GitHub 上怎么加

建仓库时可以直接选一个协议模板，GitHub 会生成 `LICENSE` 文件。已有仓库在网页上新建文件、命名为 `LICENSE`，GitHub 会弹出模板选择器。

命令行也能查模板：

```bash
gh repo license list
gh repo license view mit
```

加完之后，GitHub 会在仓库首页显示协议名称，这也是使用者判断能不能用的第一眼信息。

**注意区分 [[开源贡献流程]] 里提到的 CLA。** 协议管的是「别人怎么用你的代码」，CLA 管的是「别人贡献给你的代码，你获得什么授权」，方向相反，两者可以同时存在。
